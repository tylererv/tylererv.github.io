01

Project Description

Smooth Cruize runs YOLO detection against live cameras, webcams, IP streams, or uploaded video. When it detects a pothole, the pipeline extracts a short context clip, sends it to the FastAPI backend, stores the media in Supabase, and uses Gemini 2.5 Flash to assign a severity score and description.

The Next.js dashboard organizes those events for map review, administration, and work-order planning. The current implementation uses mock GPS coordinates, leaving real vehicle location capture as a clear next integration step.

02

Architecture

  • Detection: YOLO video processing for live and offline sources.
  • API: FastAPI endpoints for clip upload and event creation.
  • Analysis: Gemini 2.5 Flash for severity scoring and descriptions.
  • Data: Supabase Storage and PostgreSQL-backed pothole events.
03

Detection-to-Work-Order Flow

The computer vision layer supports two operating modes: a live runner for webcams and RTSP/HTTP sources, and an offline batch processor for recorded footage. The live process keeps a rolling frame buffer so a detection produces evidence from before and after the triggering frame instead of an isolated image.

  • Generated MP4 clips are posted as multipart uploads to /api/upload-clip with vehicle and coordinate metadata.
  • The backend assigns a unique filename, writes the clip to the pothole-clips Supabase Storage bucket, and passes a temporary copy to Gemini 2.5 Flash.
  • Gemini returns structured JSON with a 1–10 severity score and a concise description; the service then links pothole_events and clips records.
  • The Next.js administration interface supports severity sorting, status changes, map context, video evidence, and full work-order records.

GPS values are currently mocked by the backend. The documented next stage is to ingest coordinates from a real vehicle or transit GPS source and suppress duplicate detections within a geographic threshold.
