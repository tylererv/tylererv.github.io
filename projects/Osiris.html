Osiris

An active coding-practice prototype that maps assessment performance into personalized learning roadmaps and a local AI-guidance workflow.

GitHub Repository
01

Project Description

Osiris begins with an assessment, records performance and time data, and uses the results to recommend a sequence of coding problems. The application is designed around guided practice: its AI assistant gives Socratic hints that help a learner reason through a problem instead of returning a complete answer.

The repository defines a Next.js interface, a typed FastAPI REST surface, Supabase as the authentication and PostgreSQL boundary, and a local Ollama integration target. Assessment, roadmap, problem, progress, and AI-guidance routes are separated by responsibility; several database, JWT-verification, and model calls remain explicit prototype stubs in the current backend.

02

Tech Stack

  • Frontend: Next.js and TypeScript.
  • Backend: FastAPI REST API.
  • Data and authentication: Supabase and PostgreSQL.
  • AI guidance target: local Ollama inference with a gpt-oss model.
03

Assessment and Practice Architecture

  • Pydantic request and response models define contracts for starting and submitting assessments, loading roadmaps, retrieving problems, recording attempts, and summarizing progress.
  • The problem API is structured around hidden test cases and attempt feedback. The resume documents Docker-isolated testing environments for safer code execution.
  • The Next.js application uses Supabase session handling and protected routes as the user-facing authentication foundation.
  • The roadmap model combines assessment topics, difficulty, performance, and completion state so recommendations can change as the learner improves.
  • Ollama with a local gpt-oss model was selected to keep inference private and constrain guidance to questions, conceptual explanations, and incremental hints.

The current repository is an active prototype. Its route contracts and architecture decisions are present, while production persistence, verified Supabase JWT handling, full sandbox orchestration, and live Ollama calls remain areas of ongoing implementation.
